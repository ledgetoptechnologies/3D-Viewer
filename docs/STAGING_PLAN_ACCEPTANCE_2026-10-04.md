### Routine image/network rollback

1. Coordinate maintenance with Hermes and stop Viewer through `viewer-staging.service` before changing the owned firewall or deployment configuration.
2. Restore only the previous image/network Compose layout from baseline backup `230532Z`, using the retained old image above. Retain the **rotated** Viewer/proxy secret pair; if its recovery is necessary, use the matched pair from post-rotation snapshot `231034Z`, not baseline credentials. Do not restore the database as part of routine rollback.
3. Recreate only Viewer through the supervised service, preserving NAS preflights and Docker/mount ordering. The owned guard/drop-in can remain for the first recreation of the old layout. Remove its owned rules only after confirming API/worker are no longer attached to the edge network; disable only the owned new drop-in if restoring the old supervision layout.
4. Never apply a captured global firewall restore: those files are evidence, not a rollback command, and restoring them could change unrelated PA or host policy. Use only the guard's scoped owned-rule removal when its prerequisites are satisfied.
5. If processing tests have created jobs, keep an older processing worker stopped until all interrupted or ambiguous submissions have been reconciled. Confirm new-secret pairing without displaying values, image identity, HTTPS/authentication, mount guards and unrelated-service health before resuming work.

Keep revision, immutable digest, CI receipt and live screenshots/results here as each gate passes. Missing representative assets remain explicit gaps.
